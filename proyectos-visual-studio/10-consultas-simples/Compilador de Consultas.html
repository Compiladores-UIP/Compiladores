BProblema que resuelve

Consultar una base de datos sin saber SQL.

Para obtener información de una base de datos hay que escribir sentencias SQL como SELECT * FROM estudiante WHERE edad > 18;. Esa sintaxis en inglés, con sus cláusulas y comillas simples, es una barrera para quien empieza.

Este mini-compilador acepta la misma consulta en español. Comprueba que la tabla y los campos existan y que cada condición compare tipos compatibles, por ejemplo un número con un número. Si todo está bien, genera el SQL equivalente y lo ejecuta sobre una base de datos de ejemplo.

DTokens identificados
Las unidades léxicas de una consulta.

        
El analizador léxico separa palabras clave, nombres de tablas y campos, operadores y valores. Los operadores de dos caracteres (>=, <=, <>) se reconocen como un solo token.

EAnálisis sintáctico
La gramática y el árbol de cada consulta.

        
El analizador sintáctico es descendente recursivo: cada regla de la gramática es un método. Como en SQL, Y se evalúa antes que O. Después, el análisis semántico comprueba la consulta contra la base de datos.

      


<consulta>  ::= BUSCAR <origen> [ DONDE <filtro> ]
                [ ORDENAR POR IDENT [ ASC | DESC ] ] [ ";" ]
<origen>    ::= IDENT | <campos> DE IDENT
<campos>    ::= IDENT { "," IDENT }
<filtro>    ::= <condicion> { ( Y | O ) <condicion> }
<condicion> ::= IDENT <operador> <valor>
<operador>  ::= ">" | "<" | ">=" | "<=" | "=" | "<>"
<valor>     ::= NUMERO | DECIMAL | TEXTO

        
Consulta
├─ BUSCAR → SELECT
│  └─ Campos: * (todos)
├─ Tabla → FROM
│  └─ estudiante
└─ DONDE → WHERE
   └─ Condición: edad > 18

      

      

        

          
Validación semánticaEjemplo que la rompe

          
            
La tabla debe existirBUSCAR estudiantes

            
Cada campo debe pertenecer a la tabla… DONDE telefono = "6000"

            
Un campo numérico se compara con un número, uno de texto con un texto… DONDE edad > "veinte"

            
Los textos solo se comparan con = o <>… DONDE nombre > "Ana"

HPruebas
Un caso correcto y errores controlados.

        
Cada error indica la fase que lo detectó, la línea, la columna y una sugerencia. Usa “Probar” para cargarlo en el laboratorio.

      

        

          Caso correcto
          
BUSCAR estudiante DONDE edad > 18

          
Resultado esperado: SELECT * FROM estudiante WHERE edad > 18; devuelve 4 filas: Ana, Pedro, Sofía y Diego.

          
        

        

          Caso incorrecto
          
BUSCAR estudiante DONDE edad >

          
Mensaje esperado: Error sintáctico (línea 1, columna 31): Falta el valor después de ">".
→ El valor puede ser un número o un texto entre comillas.

          
        

      

      

        
Otros errores que detecta

        

          
buscar estudiante DONDE edad > 18Sintáctico: "buscar" no se reconoce como palabra clave. → BUSCAR va en mayúsculas

          
BUSCAR estudiantes DONDE edad > 18Semántico: La tabla "estudiantes" no existe. ¿Quisiste decir "estudiante"?

          
BUSCAR estudiante DONDE telefono = "6000-0000"Semántico: La tabla "estudiante" no tiene un campo llamado "telefono".

          
BUSCAR estudiante DONDE edad > "veinte"Semántico: El campo "edad" es numérico y se compara con un texto.

          
BUSCAR estudiante DONDE nombre = AnaSintáctico: Falta el valor después de "=". → escríbelo entre comillas

          
BUSCAR estudiante DONDE edad # 18Léxico: Símbolo no reconocido: '#'.
